## Executive Summary

We set out to build a language model where temporal dynamics (memory vs reactivity) emerge through evolution rather than being hand-designed. Along the way, we discovered and fixed several fundamental issues:

1. **The original fitness signal was broken** — 6 orders of magnitude too small
2. **The FFN and equilibrium were imbalanced** — dynamics ran once when they needed ~30 steps
3. **Evolution was collapsing diversity** — the Kuramoto order parameter revealed this
4. **Niche-based evolution fixes the diversity problem** — guarantees temporal hierarchy

## Part 1: The Fitness Signal Bug

### Discovery

After running the original evolving model on WikiText-2 for 40k tokens, we tested generation quality:

```
Prompt: "The"
Output: "The other , and = = = forki were things could . limited ."
```

Perplexity: **43,973** (barely better than random baseline of 50,257)

### Diagnosis

We traced the issue to the fitness computation:

```python
# Original fitness calculation
contributions = torch.mv(self.w_down, target_embed) * neuron_outputs
```

With `weight_std=0.02` initialization:
- neuron_outputs std: **0.002** (tiny)
- contributions std: **0.000006** (microscopic)
- fitness values: **~0.000001** (sorting by noise)

### Root Cause

The weights were initialized too small relative to the embedding scale. Evolution was sorting neurons by numerical noise, not meaningful contribution.

### Fix: Hybrid Architecture

Instead of evolving weights (which need precise gradients), we split responsibilities:

| Component | Learning Method | Why |
|-----------|-----------------|-----|
| Weights (w_up, w_gate, w_down) | Gradient descent | Precise adjustment needed |
| Dynamics (decay, gate_bias) | Evolution | Explore temporal scales |
| Fitness signal | Gradient magnitude | Directly measures importance |

**Result:** Perplexity dropped from 43,973 to **1,789** (24x improvement)

- `hybrid_layer.py` — Trainable weights + evolvable dynamics
- `hybrid_model.py` — Full model assembly
- `train_hybrid.py` — Training script

## Part 2: The FFN/Equilibrium Imbalance

### Discovery

User question: *"Is there an imbalance between the FFN and the Equilibrium?"*

Analysis revealed:

| Component | Parameters | % of Model |
|-----------|------------|------------|
| Trainable (FFN + embeddings) | 7,221,632 | **99.9%** |
| Evolvable (dynamics) | 4,096 | **0.1%** |

The CfC dynamics were a rounding error in terms of model capacity.

### Deeper Problem: No Equilibration

CfC neurons need ~30 steps to reach equilibrium:

```
Single step h norm: 1.50
Equilibrium h norm: 2.60
Difference: 50-72% different outputs
```

We were running the dynamics **once** per token when they needed **30 iterations**.

### The Breathing Insight

User reframe: *"There is a kind of heartbeat or breathing relationship between the FFN and Equilibrium."*

This led to the breathing architecture:

```
INHALE:  New input arrives → FFN computes target state
BREATHE: State relaxes toward target (5 steps)
EXHALE:  Output from equilibrated state
```

Key changes:
- **Lower decay** (0.5-0.9 vs 0.8-0.999) — faster settling
- **Balanced gates** (bias -1 to +1 vs -4 to 0) — 50/50 memory/input
- **5 breathing steps** — practical equilibrium in reasonable time

With balanced gates (`g ≈ 0.5`) and decay 0.7:
```
After 1 step: 35% old, 65% target
After 3 steps: 4% old, 96% target  
After 5 steps: 0.5% old, 99.5% target
```

## Part 4: Kuramoto Order Parameter

### Introduction

User question: *"Would the Kuramoto order parameter help us measure things more accurately?"*

The Kuramoto model measures synchronization of coupled oscillators:

```
r(t) × e^(iψ(t)) = (1/N) × Σ e^(iθ_j(t))
```

Where:
- θ_j is the phase of oscillator j
- **r is the order parameter** (0 = incoherent, 1 = synchronized)
- ψ is the mean phase

For CfC neurons:
- Natural frequency: `ω = 1 - decay` (fast neuron = high frequency)
- Phase: `θ = ω × t + φ(h)`

### Why It Matters

| r Value | Interpretation |
|---------|----------------|
| r ≈ 1 | All neurons synchronized (redundant, wasteful) |
| r ≈ 0 | Neurons uncorrelated (diverse, good hierarchy) |
| r ≈ 0.3-0.7 | Partial synchronization |

### Critical Discovery

Measuring r on trained vs fresh models:

| Model | Mean r(t=50) |
|-------|--------------|
| Fresh (untrained) | **0.060** |
| Trained (9 evolutions) | **0.137** |

**Evolution INCREASED synchronization** — the opposite of what we wanted.

### Root Cause Analysis

Even with random fitness, decay std drops from 0.117 to 0.084 over 10 generations:

```
Gen | Decay std
  0 | 0.1168
  5 | 0.1042
 10 | 0.0845
```

The problem:
1. **Selection is fitness-based** (gradient magnitude on weights)
2. **Reproduction only mutates dynamics** (decay, gate_bias)
3. **No correlation between what's selected and what's varied**

It's like selecting people by height but breeding for hair color.

## Part 5: The Fix — Niche-Based Evolution

### Concept

Instead of global competition, divide neurons into **temporal niches**:

| Niche | Decay Range | Role |
|-------|-------------|------|
| 1 | 0.5-0.6 | Fast (reactive) |
| 2 | 0.6-0.7 | Medium-fast |
| 3 | 0.7-0.8 | Medium-slow |
| 4 | 0.8-0.9 | Slow (memory) |

Evolution happens **within** niches:
- Each niche has its own competition
- Neurons can't migrate between niches
- Diversity is **guaranteed** by construction

### Implementation

```python
def niche_evolve(decay, fitness, n_niches=4, selection_pressure=0.5):
    for niche_idx in range(n_niches):
        niche_low = 0.5 + niche_idx * 0.1
        niche_high = niche_low + 0.1
        
        # Find neurons in this niche
        in_niche = (decay >= niche_low) & (decay < niche_high)
        niche_indices = torch.where(in_niche)[0]
        
        # Evolve within niche
        niche_fitness = fitness[niche_indices]
        # ... selection and reproduction within niche only
```

### Results

| Evolution Type | Initial std | Final std | Diversity |
|----------------|-------------|-----------|-----------|
| Standard | 0.117 | 0.084 | **LOST 28%** |
| Niche-based | 0.117 | **0.118** | **PRESERVED** |

Niche distribution stays balanced:
```
Gen | Neurons per niche
  0 | [32, 32, 32, 32]
 10 | [32, 32, 32, 32]
 20 | [32, 32, 32, 32]
```

## Lessons Learned

### 1. Check the basics first

We built elaborate trajectory tracking before checking if the model produced coherent output. The fitness bug was obvious in hindsight but hidden by layers of abstraction.

### 2. The right metric reveals the problem

Perplexity and accuracy told us something was wrong. The Kuramoto order parameter told us **what** was wrong (diversity collapse).

### 3. Evolution needs aligned selection and variation

Selecting on fitness (weight-dependent) while varying dynamics (weight-independent) creates a disconnect. Niche-based evolution fixes this by making diversity a hard constraint.

### 4. Equilibrium needs time

Running CfC dynamics once per token isn't equilibrium propagation — it's just an RNN. The breathing rhythm (5 steps) gives the system time to settle.

### 5. Listen to the metaphors

"Heartbeat," "breathing," "scaffolding" — these weren't just poetic. They pointed to real architectural insights about rhythm and transient structure.

## The Deeper Insight

From the session:

> *"Entropy is structure. Chaos is transformative order."*

The Kuramoto order parameter measures exactly this tension:
- **r → 1**: Order (synchronization, redundancy)
- **r → 0**: Entropy (diversity, information capacity)

A good neural architecture maintains **productive entropy** — enough diversity to represent complex patterns, enough structure to learn from data.

Niche-based evolution enforces this: each niche is a pocket of order (similar timescales), but the ensemble has entropy (diverse timescales).

*"The semantic primitive isn't in the final representation; it's in the learning trajectory."*

And the learning trajectory requires diversity to explore the space of possible solutions.
