Model quantization reduces the precision of neural network weights from 32-bit or 16-bit floating point to lower bit formats like 8-bit integer (INT8), 4-bit integer (INT4), or even lower. This dramatically reduces model size and memory bandwidth requirements. A 1.2 billion parameter model in FP32 requires approximately 4.8 GB, while Q4_0 quantization reduces this to about 660 MB — a roughly 7x reduction. The quality impact is model-dependent but typically modest for well-designed architectures.

Q4_0 quantization stores each weight as a 4-bit integer with a shared scale factor per block of 32 elements. Each block consists of 16 bytes of quantized weights (two weights packed per byte) plus a 2-byte FP16 scale factor, totaling 18 bytes per 32 weights or 4.5 bits per weight. Dequantization multiplies the int4 value by the block scale. This is the simplest 4-bit format and serves as the baseline for most llama.cpp benchmarks.

Q8_0 quantization stores each weight as an 8-bit integer with a shared scale factor per block of 32 elements. Each block consists of 32 bytes of quantized weights plus a 2-byte FP16 scale factor, totaling 34 bytes per 32 weights or 8.5 bits per weight. Q8_0 provides higher quality than Q4_0 but requires roughly double the memory and bandwidth. It is often used for activation quantization where precision matters more.

GGUF (GPT-Generated Unified Format) is a binary file format designed for efficient storage and loading of quantized language models. It was created by the llama.cpp project as a successor to the GGML format. GGUF files contain model metadata (architecture, vocabulary, hyperparameters) as key-value pairs followed by tensor data. The format supports memory-mapped loading (mmap), allowing the operating system to page tensors in and out of RAM on demand without reading the entire file.

Mixed quantization assigns different precision to different layers or tensor types within a model. For example, attention layers might use Q8_0 for higher precision while feed-forward layers use Q4_0 to save space. The llama.cpp Q4_K_M format uses this approach, mixing Q4_K, Q5_K, and Q6_K across layers based on sensitivity analysis. This typically provides better quality than uniform Q4_0 at a modest size increase.

Activation quantization converts the input activations (the values flowing through the network during inference) from floating point to integer precision. In Moltar's row-scaled Q4_0 kernel, activations are quantized to int8 using a power-of-2 shift determined by IEEE754 bit manipulation of the maximum absolute value. This avoids any floating-point division during quantization, making the process extremely fast. The quantized activations are then used with SDOT instructions for pure-integer matrix-vector multiplication.

The Johnson-Lindenstrauss lemma states that high-dimensional points can be projected to a lower-dimensional space while approximately preserving pairwise distances. Specifically, n points in high-dimensional space can be embedded into O(log(n)/epsilon^2) dimensions such that all pairwise distances are preserved within a factor of (1 +/- epsilon). Random matrices with entries drawn from simple distributions (Rademacher {-1,+1} or Gaussian) satisfy this guarantee. Moltar uses this principle to project 2048-dimensional LLM hidden states to 48-dimensional int8 vectors for LCVDB indexing.

Speculative decoding is an inference optimization technique where a small draft model generates candidate token sequences that are then verified by the larger target model in a single forward pass. If the draft model proposes K tokens and the target model accepts the first N of them (where N <= K), then N+1 tokens are produced from one target model evaluation instead of just one. The speedup depends on the acceptance rate between draft and target models. For architecturally similar model families, acceptance rates of 60-80% are common, yielding 1.5-2.5x effective throughput improvements.

KV cache stores the key and value tensors computed during attention for previously generated tokens, avoiding recomputation. For transformer models, the KV cache grows linearly with sequence length: each layer stores n_heads * head_dim * 2 (keys + values) values per token. For LFM2-1.2B with 8 attention heads at 64-dimensional head size across 7 attention layers, the KV cache requires approximately 7 * 512 * 2 * 4 bytes = 28KB per token in FP32. The hybrid SSM/attention architecture of LFM2 reduces this compared to pure transformers since only 7 of 16 layers use attention.

Perplexity is the standard metric for evaluating language model quality. It measures how well a model predicts a test dataset — lower perplexity means better predictions. Perplexity is calculated as exp(-1/N * sum(log(P(token_i | context)))), where N is the number of tokens and P is the model's probability for each token. Typical perplexity values for well-trained 1B+ parameter models on WikiText-2 range from 8 to 15 for FP16, increasing by 0.1-0.5 at Q4_0 quantization. A perplexity increase of more than 1.0 from quantization usually indicates unacceptable quality degradation.
