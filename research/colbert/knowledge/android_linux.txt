Android is built on the Linux kernel but adds several layers: HAL (Hardware Abstraction Layer), ART runtime (Android Runtime for Java/Kotlin apps), system services (SurfaceFlinger, ActivityManager, PackageManager), and the application framework. The Linux kernel handles memory management, process scheduling, and device drivers. On rooted devices, the su binary provides superuser access, allowing direct kernel parameter modification, process control, and filesystem access that are normally restricted.

Memory-mapped I/O (mmap) maps a file directly into a process's virtual address space. Instead of read() system calls that copy data from kernel buffers to user space, mmap allows the CPU to access file data through page faults. When a page is first accessed, the kernel loads it from disk into the page cache. Subsequent accesses hit the page cache directly. This is how llama.cpp loads GGUF model files — the 661 MB model is mmap'd, and the OS manages which pages are in RAM based on access patterns and memory pressure.

The Linux page cache is an in-memory cache of file data managed by the kernel. When a file is read, pages (typically 4 KB each) are cached in RAM. When memory pressure increases, the kernel evicts least-recently-used pages. For LLM inference with mmap'd models, the page cache behavior is critical: if another process (like ColBERT embedding) allocates significant memory, the kernel may evict model pages from the page cache, requiring them to be re-read from flash storage when next accessed. This is the model swap cost observed in Moltar's RAG pipeline.

The Android process zygote is the parent process for all Android application processes. When Android framework services are running, zygote, SurfaceFlinger, system_server, and dozens of other services consume approximately 1.5-2 GB of RAM and 4 GB/s of DRAM bandwidth on the Moto G Power. Running the stop command kills these services, freeing RAM for the page cache and DRAM bandwidth for inference. The start command restarts them when normal phone use is needed.

Taskset is a Linux utility that sets CPU affinity for a process. The command taskset c0 pins a process to CPUs 6 and 7 (bitmask 0xC0 = 1100_0000 in binary), which correspond to the two Cortex-A78 big cores on MediaTek Dimensity 930. Without CPU affinity, the Linux scheduler may migrate inference threads to the slower A55 cores, causing severe performance variation. CPU affinity combined with the performance governor ensures consistent inference throughput.

Magisk is a rooting solution for Android devices that provides systemless root access. It modifies the boot image to inject the su binary without modifying the system partition, allowing the device to pass SafetyNet checks. Magisk modules can install scripts that run during boot, such as the moltar_perf.sh script that stops Android framework services and sets CPU governors. The Moto G Power's bootloader can be unlocked through Motorola's official process, enabling Magisk installation.

CPU frequency governors on Linux control how the CPU frequency scales in response to load. The performance governor locks the CPU at maximum frequency, providing consistent performance but consuming more power. The schedutil governor adjusts frequency based on scheduler utilization metrics, balancing performance and power. The powersave governor locks at minimum frequency. For inference workloads, the performance governor eliminates frequency ramp-up latency that can cause inconsistent token generation times.

The Linux OOM (Out Of Memory) killer terminates processes when the system runs critically low on memory. It assigns an oom_score to each process based on memory usage and importance. Processes with higher oom_score are killed first. For on-device LLM inference, the mmap'd model file doesn't count toward process RSS (Resident Set Size) since it's file-backed and can be reclaimed by evicting pages. This means the inference process is unlikely to be OOM-killed even with large models, as long as heap allocations are reasonable.

ADB (Android Debug Bridge) enables communication between a host computer and an Android device over USB or WiFi. Key commands include adb shell for interactive terminal access, adb push/pull for file transfer, and adb forward for TCP port forwarding. Port forwarding with adb forward tcp:8080 tcp:8080 tunnels connections from the host's port 8080 to the device's port 8080, enabling browser access to servers running on the device without knowing the device's IP address. ADB works on rooted and unrooted devices alike.

Termux is a terminal emulator and Linux environment for Android that runs without root access. It provides a package manager (pkg) with common Linux utilities, compilers, and interpreters. The Termux:Boot add-on allows scripts to run automatically when the device boots by placing them in the ~/.termux/boot/ directory. This is useful for starting background services like moltar-server without manual intervention after a device restart. Termux processes run with the app's UID and can use su for root operations on rooted devices.
